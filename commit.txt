Erdős-Straus: the file claimed the conjecture, and the statement was empty

ErdosStrausProof.lean was 1175 lines asserting the whole Erdős-Straus conjecture,
sorry-free. Three things were wrong with it, and nothing had ever checked any of
them: the file imported Mathlib.NumberTheory.Primes, which does not exist in this
toolchain, and it was absent from the lakefile, so it never compiled.

The statement was empty. `structure Solution` carried
4*x*y*z = n*(y*z + x*z + x*y) with `n` appearing nowhere in its parameters, and
the main theorem read `erdos_straus (n : ℕ) (hn : n ≥ 2) : ∃ (sol : Solution)`.
The conclusion does not mention n. Whatever n the structure's equation referred
to, it was not the n the theorem quantified over. Solution now takes n as a
parameter and the theorem concludes about that n.

One family was arithmetically false. solve_mod12_9 set x = 3k+3 and
y = z = (12k+9)(k+1), which at k=0 is 1/3 + 1/9 + 1/9 = 5/9 against 4/9. Each
tail is half what it should be: 4/n − 1/(3k+3) = 1/(n(k+1)), so splitting it in
two gives y = z = 2n(k+1). old_mod12_9_fails and new_mod12_9_holds record both
sides of that at k=0.

And it constructed a solution for the open case. solve_mod4_1_not3 claimed to
build one for n ≡ 1 (mod 4) with 3 ∤ n, out of a CRT search for d with
d ≡ 3 (mod 4), d ≡ 0 (mod 3), d ≡ −n (mod 5). That case IS the conjecture. It is
a Prop here and is not constructed.

What survives is real and is now proved: every n ≥ 2 outside that one class has
an explicit solution, by four parametric families — even, 4k+3, 4k+2 and the
corrected 12k+9 — each a ring identity once cleared of denominators.
erdos_straus_off_open_case is that theorem, and conjecture_iff_open_case shows
the conjecture is exactly the open class away, with the converse immediate. So
the gap is located rather than papered over.

The file is in the lakefile now, so it is checked. Standard axioms.
